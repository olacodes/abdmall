# 1. Project Overview

This quotation covers the design, development, and launch of a mobile e-commerce application for iOS
and Android. The app is built from a single cross-platform codebase, allowing both platforms to be
delivered on one timeline while sharing a common backend. The initial release (v1) is scoped for a fast,
focused launch: customers can browse products, add them to a cart, and pay securely — with the option
to add richer features in a later phase. A matching web storefront is available as an optional add-on (see
Section 5), running on the same backend so your catalogue and payments are managed once across every
channel.

## 2. Scope of Work

The v1 application comprises the following:
● Homepage with featured products, categories, and clear navigation.
● Product catalogue with category browsing, search, and detailed product pages.
● Shopping cart with add/remove items and quantity management.
● Secure checkout with Paystack payment integration and server-side transaction verification
(payment status is never trusted from the device).
● Guest checkout — no mandatory account creation, to reduce friction at purchase.
● Order confirmation and a basic order-history view for returning customers.
● Backend (database, secure storage, and APIs) provisioned on Supabase.
● Deployment & submission to both the Apple App Store and Google Play, including build
configuration and store listings.

## 5. Optional Add-On — Web Application

If you’d also like customers to buy from a web browser — desktop, tablet, or mobile web — alongside the
mobile apps, we can add a responsive web storefront. It offers the same core commerce experience: a
homepage, product catalogue with search, product pages, a shopping cart, and secure Paystack checkout
with the same server-side verification.
Why it’s an add-on, not a second build: the web storefront runs on the same Supabase backend,
database, and Paystack payment integration built for the mobile app. Your products are managed in one
place and reflected everywhere — across iOS, Android, and the web — so the web application is priced as
an incremental addition rather than a full second project.
