# abdmall — Supabase backend

Schema-as-code for the abdmall backend. Everything here is versioned SQL — no
tables are created by hand in the dashboard.

## Layout

```
supabase/
├─ migrations/
│  ├─ 20260804120000_catalogue.sql   # enums, categories, products, search, RLS
│  ├─ 20260804120100_profiles.sql    # profiles, addresses, new-user trigger, RLS
│  └─ 20260804120200_orders.sql      # orders, order_items, RLS (server-write only)
├─ seed.sql                          # categories + sample products
└─ config.toml                       # generated by `supabase init` (not hand-written)
```

Migrations apply in filename (timestamp) order.

## First-time setup

```bash
# once, globally
npm i -g supabase          # or: brew install supabase/tap/supabase

# in the repo
supabase init              # creates supabase/config.toml (keep the migrations/ we already have)
supabase link --project-ref <your-project-ref>
```

## Apply the schema

```bash
# to the hosted project
supabase db push

# or run everything locally (Docker) first, incl. seed.sql
supabase start
supabase db reset
```

Prefer the CLI. If you'd rather not install it yet, the same three migration
files can be pasted (in order) into the dashboard **SQL Editor** and run — the
files stay the source of truth in the repo either way.

## Generate TypeScript types for the Next.js app

```bash
supabase gen types typescript --linked > src/lib/database.types.ts
```

This gives the frontend fully-typed queries when we replace the mock data layer.

## Notes / decisions baked into the schema

- **Money is server-authoritative.** `orders` / `order_items` have *no* client
  insert/update policies. Orders are created and marked `paid` only by the
  server (service role) after Paystack verification.
- **Guest checkout** needs no account: `orders.user_id` is nullable; guest
  orders are fetched by `reference` server-side.
- **History is immutable.** `order_items` snapshot name/price/image at purchase.
- **Catalogue is public-read** via RLS; merchant writes go through the service
  role (Supabase Studio or a server admin path).
- **Cart stays client-side** for v1 (localStorage), so there is no cart table.
  Adding one for signed-in, cross-device carts is a clean future migration.
- **Images**: `image_url` currently points at the local `/products/*` files; a
  later migration moves them to a public Storage bucket and rewrites the URLs.

## Seed data (generated)

`seed.sql` is **generated** from the single source of truth in
`src/lib/mock-data.ts` — all 6 categories and all 48 products — so it never
drifts from the frontend catalogue. Do not edit it by hand. To regenerate after
changing the mock data:

```bash
npx tsx scripts/generate-seed.ts
```

Products resolve their `category_id` by slug via a `values … join categories`,
so the file stays order-independent and readable.
